# 微服务架构与云原生研效演进

| 字段 | 内容 |
|------|------|
| **角色** | 技术负责人 |
| **周期** | 2019 – 2026（持续演进） |
| **公司** | 腾讯 · 超核 / 商业化 / AI 工程 |
| **产业** | [互联网平台建设与研效](../行业解决方案.md) |

## 展示摘要

在多条业务线并行迭代下，统一超核 **TRPC 微服务底座、K8s 上云与 OpenTelemetry 可观测**，把发布从 **18 步压到 7 步**、可用性拉到 **99.99%**、资源成本 **-25%**，并支撑 30 亿+ 商城与亿级 AI 交互而不拖慢业务。

## 一句话

主导超核系 **TRPC 微服务标准化、全量上云、OpenTelemetry 可观测与研效流程再造**，支撑百亿级业务；可用性 **99.99%**，流程 **18→7 步**，资源成本 **-25%**。

---

## 技术挑战与约束

| 挑战 | 具体表现 | 约束 |
|------|----------|------|
| 架构碎片化 | 商城、活动、AI 各有一套 RPC/配置/发布习惯 | 不能停机大改，须灰度迁移 |
| 发布与质量 | 人工步骤多，回滚慢，变更失败率高 | 业务大促窗口禁止冒险发布 |
| 可观测缺失 | 故障需跨 5+ 系统查日志，MTTR 以小时计 | 需对齐公司 OTel 标准 |
| 成本与容量 | 资源预留激进，利用率低 | FinOps 要求可度量降本 |
| 组织协同 | 多团队共用底座，标准难统一 | 用脚手架与 RFC 降低说服成本 |

**非目标：** 本阶段不替换业务领域模型（DDD 拆分由各业务线主导）；不一次性废弃 PHP 遗留，采用**绞杀者**逐步迁移。

---

## 关键架构决策

| 决策 | 选型 | 备选与取舍 |
|------|------|------------|
| RPC 与契约 | **TRPC + Protobuf** + 大仓 PB 模板 | gRPC 裸用：缺少腾讯内治理组件整合；自研 RPC：维护成本过高 |
| 注册与配置 | **北极星 + 七彩石** | 纯 K8s Service：不满足多环境与灰度配置习惯 |
| 南北向流量 | **APISIX** 统一网关 | 每服务自建 Ingress：策略分散、难审计 |
| 运行与弹性 | **全量 K8s** | 物理机混部：弹性差；仅容器不编排：发布仍重 |
| 可观测 | **OpenTelemetry 三件套**（日志/指标/链路） | 各业务自建监控：口径不一，专利级标准难复用 |
| 研效 | **蓝盾流水线 + 代码生成脚手架** | 保留 18 步人工：无法支撑 10+ 渠道与 AI 线并行 |

---

## 情境（Situation）

- 业务从 PHP/单体走向 Go/微服务，渠道与活动激增，发布步骤冗长、故障定位难。
- 多条线（商城、活动、AI）共用研发体系，缺乏统一框架与可观测标准。
- 需在**不拖慢业务**前提下完成架构升级与降本。

## 任务（Task）

- 设计并推广超核统一微服务研效方案与脚手架。
- 推动 K8s 上云、服务治理、CI/CD 与质量门禁。
- 参与 **OpenTelemetry** 公司级标准落地（获腾讯专利奖）。

## 行动（Action）

### 演进时间线

| 阶段 | 时间 | 里程碑 |
|------|------|--------|
| 标准化 | 2019–2021 | TRPC 试点 → 超核核心域迁移；发布平台对接蓝盾 |
| 上云与治理 | 2021–2023 | K8s 全量；北极星/七彩石/APISIX 统一；商城/活动中台接入 |
| 可观测 | 2022–2024 | OTel 规范落地；链路覆盖核心交易与 AI 网关 |
| 降本与研效 | 2023–2025 | 资源治理 -25%；18→7 步；AIOps 探索（见独立项目） |

### 微服务与 DevOps

- **TRPC + Protobuf** 标准化；七彩石、北极星、APISIX、智研/蓝盾整合。
- **大仓 + PB 模板 + 代码生成**，微服务拆分「零负担」。
- 发布流程从 **18 步优化为 7 步**；代码自动化部署率 **100%**。

### 可观测与稳定性

- 统一日志、指标、分布式链路追踪。
- 压测基线、容量评估、告警分级与复盘机制。
- 支撑商城、活动、AI 等线 **99.95%–99.99%** 可用性目标。

### 成本与治理

- K8s 弹性与资源治理，**资源成本降低约 25%**。
- 架构评审（RFC）、技术债与版本治理。

### AI 研效（2025+）

- 详见独立项目：[AI 驱动研效平台](2025-2026_AIOps智能研效平台.md)。

## 结果（Result）

| 指标 | 结果 | 说明 |
|------|------|------|
| 可用性 | 99.95%–99.99% | 商城、活动、AI 核心链路 |
| 发布流程 | 18 步 → **7 步** | 含协议生成、扫描、部署 |
| 部署自动化 | **100%** | 蓝盾流水线默认路径 |
| 资源成本 | **约 -25%** | K8s 弹性 + 治理 |
| 研效 | +20%～50%+ | 各业务线口径 |
| 专利 | OpenTelemetry 相关 | 腾讯专利奖 |
| 业务支撑 | 30 亿+ 年流水商城、百万级活动、亿级 AI 调用 | 同一底座 |
