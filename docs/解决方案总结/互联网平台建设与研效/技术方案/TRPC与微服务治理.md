# TRPC 与微服务治理 · 技术方案

## 1. 背景

超核多条业务线（商城、活动、AI）并行迭代，需要统一 **RPC 框架、配置、注册发现、网关与发布流程**，避免「每个项目一套治理」。

---

## 2. 标准技术栈

| 组件 | 职责 |
|------|------|
| **TRPC + Protobuf** | 服务契约、多语言生成、高性能 RPC |
| **北极星** | 注册发现、负载均衡、健康检查 |
| **七彩石** | 配置中心、灰度、热更新 |
| **APISIX** | 南北向网关、限流、鉴权 |
| **智研 / 蓝鲸** | 日志、指标、告警 |
| **蓝盾** | CI/CD、流水线、质量门禁 |
| **K8s** | 容器编排、弹性伸缩 |

---

## 3. 研效脚手架（18 步 → 7 步）

**合并前典型痛点：** 协议生成、依赖管理、环境申请、发布审批分散在多个系统。

**做法：**

- **大仓代码管理** + 超核定制 PB 模板。
- **代码生成脚手架**：服务骨架、DAO、配置一键生成。
- **协议自动化 CI/CD**：Proto 变更自动触发编译与兼容性检查。
- **流水线整合**：构建、扫描、部署串联。

**结果：** 新服务接入成本显著下降，团队反馈研发流程效率 +20%～50%。

---

## 4. 服务治理要点

- **接口版本化**与向后兼容策略。
- **超时、重试、熔断**默认配置模板。
- **限流分级**：核心交易链路优先保障。
- **灰度发布**：按实例/地域/用户分段。

---

## 5. 与业务中台关系

- 商城、活动中台各域服务均跑在同一套治理底座上。
- AI 服务（Lily、Virtual Idol）同样接入北极星/七彩石，统一运维视图。
