# 可观测与 OpenTelemetry 实践 · 技术方案

> **层级：** L2+ · **上级：** [行业解决方案](../行业解决方案.md)

---

## 1. 背景

微服务规模扩大后，**故障定位**从「看单服务日志」变为「跨数十个 Trace」。团队参与公司 **OpenTelemetry** 技术标准制定并落地，获**腾讯专利奖**。

---

## 2. 可观测三支柱

| 支柱 | 实践 |
|------|------|
| **Logs** | 结构化日志、统一采集、关联 TraceID |
| **Metrics** | 黄金指标（延迟、流量、错误、饱和度）；业务指标（下单成功率等） |
| **Traces** | 分布式链路；跨 TRPC/HTTP/DB/缓存 |

---

## 3. 落地架构

```
  业务服务 (TRPC/HTTP)
        │  SDK (OTel)
        ▼
  Collector / Agent
        ▼
  ┌─────────┬─────────┬─────────┐
  │ 日志平台 │ 指标平台 │ 链路平台 │
  └─────────┴─────────┴─────────┘
        ▼
  告警 → 值班 → Postmortem → 知识库(AIOps)
```

---

## 4. 业务监控（电商向）

- 交易链路专属大盘：下单、支付、发货、退款。
- **异常交易秒级识别**，与商城「零资损」目标对齐。
- 与 [尊享商城](../../电商与消费科技/项目经验/腾讯/2020-2024_尊享商城.md) 业务监控需求一体设计。

---

## 5. AI 服务可观测

- Lily / NPC：**Prometheus 全链路** + 模型延迟、GPU、降级次数。
- 流式接口：首字延迟、断流率、并发连接数。

---

## 6. 成果指标

- 故障定位效率提升约 **80%**（商城架构师口径）。
- 支撑 **99.95%–99.99%** 可用性治理。
- 为 [AIOps 排障](AIOps智能研效平台.md) 提供数据基础。

---

OpenTelemetry · Prometheus · 智研 · SkyWalking/TJG（内部）· Grafana · 自定义 Exporter
