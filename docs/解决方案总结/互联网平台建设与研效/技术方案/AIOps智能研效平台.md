## 1. 背景与目标

**痛点：** 工具链割裂导致需求—代码—运维上下文丢失；故障定位需人工跨 5+ 平台查阅，MTTR 长。

**目标：**

- 构建「需求 → 开发 → 测试 → 运维」**全链路 AI 协同**。
- 用 Agent + RAG 实现**可解释**的自动排障与知识沉淀。
- 可度量：研效 +50%、排障时间 -90%、交付物沉淀完整度 90%+。

## 3. 核心模块

### 3.1 指挥官与多 Agent

- **单一调度入口**，避免 Agent 互相踩踏；任务分解、工具授权、结果汇总。
- 子 Agent 按阶段专业化：需求澄清、代码建议、用例生成、排障根因。

### 3.2 跨工具数据层（Agentic RAG）

- 对 TAPD 需求、MR、提交、日志、指标、Trace 建立**统一检索索引**。
- 故障时自动拼装「时间线」：变更 + 日志 + 关联需求。
- 多轮追问收敛根因，而非一次性幻觉回答。

### 3.3 知识沉淀

- Postmortem / 缺陷单自动结构化入库。
- 支持「类似事故」检索，降低新人成本。

### 3.4 企微 AI 分身

- 日常研发问答、排障辅助、流程提醒嵌入 IM，降低切换成本。

## 4. 非功能设计

| 维度 | 做法 |
|------|------|
| 安全 | 代码/日志脱敏；权限与审计 |
| 成本 | 模型路由；缓存高频问答 |
| 可靠 | 人工确认关键操作；降级为检索+模板 |
| 可观测 | Agent 调用链、命中率、用户反馈闭环 |

---

## 5. 关键决策

| 决策 | 理由 |
|------|------|
| 先贯通数据再做大模型微调 | 数据孤岛是主要瓶颈 |
| 指挥官模式 vs 完全自治 | 可控、可审计，适合企业内网 |
| RAG 优先于全量微调 | 迭代快、合规风险低 |
