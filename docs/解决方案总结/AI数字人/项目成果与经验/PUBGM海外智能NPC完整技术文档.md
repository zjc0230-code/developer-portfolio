# PUBGM海外智能NPC项目完整技术文档

## 一、项目概述

### 1.1 项目背景

PUBGM海外智能NPC(Lily)是腾讯IEG技术团队核心骨干主导的创新项目,旨在通过大语言模型(LLM)和智能Agent技术,为海外PUBG Mobile用户提供智能对话服务。该项目从2024年7月开始启动,2024年11月成功上线,是知几智能NPC探索的重要里程碑。

**核心目标:**
- 为海外PUBG Mobile用户提供多语言智能对话服务
- 支持中、英、阿拉伯语等多种语言
- 实现多模态标签返回(文本、动作、语音、表情、跳转)
- 提供首问和对话两种交互场景
- 支持付费和免费用户差异化服务

## 二、技术架构

### 2.1 整体架构

PUBGM海外智能NPC采用分层架构设计,主要包含以下核心组件:

```
┌─────────────────────────────────────────────────────────┐
│                    游戏客户端                              │
│              (PUBG Mobile 海外版)                          │
└────────────────────┬────────────────────────────────────┘
                     │ HTTP/SSE
                     │
┌────────────────────▼────────────────────────────────────┐
│              pubgm-ai 服务层                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│  │ 接入层   │  │ 业务逻辑 │  │ 数据处理 │              │
│  └──────────┘  └──────────┘  └──────────┘              │
└────────────────────┬────────────────────────────────────┘
                     │
    ┌────────────────┼────────────────┐
    │                │                │
┌───▼────┐     ┌─────▼────┐    ┌──────▼─────┐
│ LLM    │     │ IDIP    │    │ ACE敏感词  │
│ 大模型  │     │ 游戏数据 │    │ 检测       │
└────────┘     └─────────┘    └────────────┘
```

### 2.2 核心组件

#### 2.2.1 接入层

**功能**: 
- 处理HTTP/SSE请求
- 签名校验和鉴权
- 限流和降级

**技术栈**:
- 协议: HTTP/SSE (Server-Sent Events)
- 框架: tRPC-Go
- 签名算法: MD5

#### 2.2.2 业务逻辑层

**功能**:
- 对话上下文管理
- 首问和对话逻辑处理
- 多模态标签生成
- 摘要和画像管理

**关键功能模块**:
1. **首问服务** (First Question)
   - 基于游戏数据生成个性化首问
   - 支持气泡内容触发
   - 首问请求不调用大模型,降低负载

2. **对话服务** (Dialogue)
   - 调用大模型生成回复
   - 上下文记忆管理
   - 支持多轮对话

3. **标签服务** (Tags Service)
   - 动作标签 (Action)
   - 表情标签 (Expression)
   - 语音标签 (Voice)
   - 转换标签 (Trans)

#### 2.2.3 数据处理层

**功能**:
- IDIP游戏数据获取
- 知识库检索
- 摘要生成和存储

**数据源**:
- IDIP接口: 获取用户游戏数据
- 知识库: 预定义的游戏知识
- 摘要服务: 历史对话摘要

### 3.2 签名校验机制

#### 3.2.1 签名算法

**第一步**: 将所有非空参数按参数名ASCII码从小到大排序,使用URL键值对格式拼接成字符串stringA

**规则**:
- 参数名按字典序排序
- 参数值为空不参与签名
- 参数名区分大小写
- 复合结构ext、game_data不需要拼接校验串

**第二步**: 在stringA最后拼接key,对signURL进行MD5运算,将结果转换为大写得到sign值

**示例**:

```
aibot_id=Lily&game_id=1342&language=zh-CN&open_id=77812392265000&query=你好,玩排位吗&scene=1&session_id=10000&source=pubgm&timestamp=123456456&trace_id=123456456&type=2&use_summary_memory=0&user_type=1&key=d317035dbf0gfc2grfv58f658c446hdf4a6
```

## 四、服务降级策略

### 4.1 可降级功能

| 功能特性 | 应用范围 | 效果分类 | 预估效果 |
|---------|---------|---------|---------|
| 免费用户的标签功能 | 免费用户对话时动作标签 | 影响功能 | 每个请求减少一次大模型调用,负载约减少1/3 |
| 付费用户的标签功能 | 付费用户局内的对话时的动作 | 影响功能 | 每个请求减少一次大模型调用,负载约减少1/3 |
| IDIP数据接口 | 付费用户的对话生成 | 影响对话生成效果 | 每个请求减少一次idip调用,影响请求耗时 |
| 摘要及画像生成 | 付费用户的对话生成 | 影响对话生成效果 | 每10个请求减少2次大模型调用 |
| 摘要及画像使用 | 付费用户的对话生成 | 影响对话生成效果 | 摘要及画像的使用,需要获取摘要画像数据 |
| 个性化首问 | 付费用户的首轮对话生成 | 影响对话生成效果 | 首问请求不调用大模型,负载影响看首问的数量 |

### 4.2 降级策略状态

| 策略状态 | S0 | S1 | S2 | S3 | S4 |
|---------|-----|-----|-----|-----|-----|
| 策略定义 | 初始态/正常态 | 免费用户限流态 | 动作标签降级态 | 对话效果降级态 | 付费用户限流态 |
| 触发条件 | - | T0 < QPS < T1 | T1 < QPS < T2 | T2 < QPS < T3 | T3 < QPS |
| 主逻辑:免费 | 正常服务 | 限流(减少50%) | 限流(减少80%) | 不服务 | 不服务 |
| 主逻辑:付费 | 正常服务 | 正常服务 | 关闭动作标签 | 关闭动作标签+摘要画像+首问 | 关闭动作标签+摘要画像+首问+功能限流 |
| 影响效果 | 正常 | 免费用户排队限流 | 失去动作效果 | 降低对话效果 | 付费用户限流 |

### 4.3 触发条件阈值

| 触发条件 | T0 | T1 | T2 | T3 |
|---------|----|----|----|----|
| 压力测试 | 全功能最大峰值QPS1 | QPS1 * 0.6 | QPS2 * 0.8 | QPS3 * 0.8 |

**压测说明**:
- T1: 全功能流程进行压力测试,延时<5s前提下,得到全功能最大峰值QPS1
- T2: 全服付费用户,去掉标签功能,延时<5s前提下,得到峰值QPS2
- T3: 全服付费用户,去掉标签功能+摘要及画像+首问功能,延时<5s前提下,得到QPS3

### 4.4 升级处理

- 升级处理只判断是否升级到S0
- 在10个周期内,qps都不满足触发条件,则升级到上一级状态

**监控维度**:

**监控平台**: 蓝鲸监控平台

**监控指标**:
- 请求量
- 失败数
- 成功数
- 耗时
- 平均耗时
- 超时数

### 8.2 线上问题定位步骤

1. vlink侧收到告警后,根据现有的告警信息确定出问题的服务
2. 根据告警信息确定大概的问题,需要运维协助查看日志
3. 查看日志需要在腾讯云日志服务进行检索
4. vlink侧根据相关日志定位出具体问题进行相关修复

### 8.3 修复方案


#### 8.4.2 知识库更新

**临时方案**: 需要运维协助操作,将具体的知识库文件打包在镜像中,通过更新镜像的方式进行更新

**最终方案**: 开发一个上传知识库文件工具页面,将该文件传到cos存储桶,同时给服务发送一个信号量告知有新的知识库内容更新,服务收到信号量会从cos存储桶中实时拉取最新的知识库文件

## 十、技术亮点与创新

### 10.1 技术创新点

1. **多模态AI对话**: 支持文本、动作、语音、表情、跳转等多种模态标签
2. **多语言支持**: 支持18种语言,涵盖全球主要语种

6. **私有化部署**: 海外独立部署,满足合规要求

### 10.2 工程实践

1. **SSE流式协议**: 提升用户体验,实时对话响应
2. **签名校验**: 简单有效的安全防护机制
3. **多级降级**: 保障系统稳定性,优先服务付费用户
4. **精细化监控**: 全链路监控,快速定位问题
5. **知识库管理**: COS+信号量机制,实时更新知识

## 十二、经验总结与反思

### 12.1 项目成功要素

1. **团队技术实力**: 腾讯IEG技术团队核心骨干,具备丰富的大模型和AI应用开发经验
2. **技术架构设计**: 分层架构,模块化设计,易于扩展和维护
3. **风险控制**: 完善的降级策略和监控体系,保障系统稳定性
4. **快速迭代**: 从启动到上线仅用4个月时间,敏捷开发模式

### 12.2 技术挑战与解决方案

| 挑战 | 解决方案 |
|-----|---------|
| 多语言支持 | 支持多种语言模型配置,通过language参数指定 |
| 大模型成本 | 首问优化、摘要缓存、降级策略多管齐下 |
| 海外合规 | 私有化部署、ACE敏感词检测、签名鉴权 |
| 高并发场景 | 五级降级策略、GPU动态扩缩容、精细化限流 |
| 知识库更新 | COS+信号量机制,实时更新无需重启服务 |

### 12.3 未来优化方向

1. **多Agent架构**: 从单Agent向多Agent架构演进,支持更复杂的场景
2. **模型效果优化**: 持续优化prompt,提升对话质量
3. **成本优化**: 进一步降低大模型调用成本,提升ROI
4. **知识库增强**: 引入RAG技术,提升知识检索能力
5. **实时学习**: 引入强化学习,根据用户反馈持续优化
