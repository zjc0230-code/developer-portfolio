# 尊享商城 / 商城中台

| 字段 | 内容 |
|------|------|
| **角色** | 项目主要负责人 / 架构负责人 |
| **周期** | 2020.01 – 至今（中台化 2022 起） |
| **公司** | 腾讯 · 超核商业化 |
| **产业** | [电商与消费科技](../../行业解决方案.md) |

## 一句话

超核高付费用户专属道具商城，**日流水百万级、年流水 30 亿+**；2022 年升级为商城中台，支撑 10+ 渠道、61 款游戏，**大迁移 0 事故**，付费转化 +18%。

---

## 情境（Situation）

- 2020 年需从 0 搭建面向腾讯全游戏**高付费用户**的专属商城（道具 + 大额充值）。
- 2022 年起多品牌渠道（尊享、心悦、知几等）快速扩张，单体架构无法支撑。
- 高并发下存在超买超卖、重复支付等**资损风险**；微服务增多后故障定位困难。

## 任务（Task）

- 0→1 架构与核心交易链路；主导 2022 **平台化改造**与领域拆分。
- 建设业务监控与事务一致性体系，保障**交易零资损**目标。
- 推动组件复用，缩短新渠道/新游戏接入周期。

## 行动（Action）

### 0→1 与交易中台

- 设计商城核心领域模型：商品、订单、支付、限购、发货策略。
- **事务型开发**保证道具购买、大额充值、合并发货等链路一致性。
- 聚合支付与游戏内限购打通（如魂斗罗自动上架等运营能力）。

### 中台化（2022+）

- 将尊享商城升级为**商城中台**，多渠道配置化接入。
- 核心能力抽象：打包售卖、合并发货、插件化营销、代币、周月卡等。
- 新商城接入周期从约 **3 个月缩短至约 3 周**（架构师口径约 70%）。

### 安全与研效

- **业务监控系统**：实时识别交易异常，秒级告警。
- 幂等 + 分布式锁，应对高并发超买超卖。
- 基于 TRPC 标准化框架，参与 **OpenTelemetry** 可观测建设（专利奖相关实践）。

### 大商城迁移

- 梳理 **30 项迁移确认点**，开发迁移工具。
- **60 款游戏**迁移完成，**0 起现网事故**（2022.10.26 节点）。

## 结果（Result）

| 指标 | 结果 |
|------|------|
| 规模 | 2023 年接入 61 款游戏（手游 59、端游 2） |
| 流水 | 年流水超 30 亿；2022 H2 较 H1 +230% |
| 渠道 | 10+ 商城渠道稳定运行 |
| 复用 | 业务组件复用率约 60%，新渠道成本约 -50% |
| 稳定 | 系统可用性 99.99%；峰值 QPS 10 万+（架构师口径） |
| 商业 | 高付费用户付费转化率 +18% |
| 安全 | 长期交易资损防控体系化 |

Golang · TRPC · 微服务 · MySQL · Redis · K8s · DDD · 事务型开发 · 业务监控 · OpenTelemetry
