# docs 维护指南

## 目录契约（勿破坏）

```
docs/
├── 个人信息.md                 # 唯一 L1
├── 能力全景图.md               # 跨产业索引（可选读）
├── 改进建议.md                 # 路线图
├── 维护指南.md                 # 本文件
├── _templates/                 # 复制用模板
├── 行业解决方案/<产业>/
│   ├── README.md
│   ├── 行业解决方案.md         # L2 宏观（必填）
│   ├── 技术方案/               # L2+（建议有）
│   └── 项目经验/               # L3（必填）
├── 博客/
└── 内部资料/                   # 不默认公开
```

## 新增内容时的规则

| 操作 | 做法 |
|------|------|
| 新产业方向 | 复制 `_templates/产业目录说明.md`，建齐四层文件 |
| 新项目 | 只在对应产业 `项目经验/` 下新增；文首链到 L2/L2+ |
| 新架构长文 | 放 `技术方案/`，文首注明 `level: L2+` |
| 重复内容 | 产业方案写方法论，技术方案写实现，项目写 STAR；禁止三处全文复制 |

## 链接规范

- 产业目录名：**中文全称**，与文件夹一致（当前平台产业为 `互联网平台建设与研效`）。
- 相对路径：同产业内用 `../行业解决方案.md`；跨产业用 `../../<产业>/...`。
- 附件：大图/PDF 放 `项目经验/<项目>/assets/`，在 README 登记。

## docs → web 同步契约

`web/src/data/site.json` 建议字段与 docs 映射：

| site.json 字段 | docs 来源 |
|----------------|-----------|
| `hero` / `bio` | `个人信息.md` 摘要段 |
| `industries[]` | `行业解决方案/<产业>/README.md` + `行业解决方案.md` 一句话 |
| `projects[]` | L3 文首表格 + `## 一句话` + `## 结果` 指标表 |
| `blog[]` | `博客/` 目录索引 |

**同步原则：** docs 为唯一事实来源；带 frontmatter 的 L3 优先机器解析。实施前见 [改进建议](改进建议.md) P1。

## 与内部资料关系

- 裁剪简历：从 `个人信息.md` + 目标产业 L3 抽取，不直接复制 `内部资料/周金成全量…` 到对外页。
- `内部资料/简历方向/` 仅保留页眉标题参考。
