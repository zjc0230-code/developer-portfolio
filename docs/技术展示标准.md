# 技术展示内容标准

> **定位：** `docs/` 是专业技术展示页的**唯一事实来源**（SSOT）。当前多数文档属于「简历级基础信息」；达到本标准后，经 `npm run sync:site` 才能在页面上呈现**架构师/技术负责人**应有的深度与可信度。

**关联：** [展示内容路线图](展示内容路线图.md) · [维护指南](维护指南.md) · [web 站点](../web/README.md)

---

## 1. 展示页 vs 知识库

| 维度 | 基础信息（现状） | 专业展示（目标） |
|------|------------------|------------------|
| 叙事 | 职责罗列、指标堆砌 | **问题 → 约束 → 决策 → 权衡 → 结果** |
| 证据 | 一句话 + 表格 | 架构图、决策表、前后对比、可复述面试故事 |
| 结构 | 简历章节 | L1 英雄区 → L2 产业格局 → L2+ 技术深潜 → L3 案例 |
| 读者 | HR / 初筛 | 技术决策者、架构评委、业务负责人 |

## 2. 分层质量门槛

### L1 · [个人信息.md](个人信息.md)

**必备：**

- `## 对外技术展示`：80–120 字英雄叙事（不重复自我评价）。
- `## 精选技术案例`：3–5 个置顶案例表（含 doc 链接、产业、一句亮点）。
- `### 量化成果`：6–8 行可扫描指标（已用于 sync）。

**避免：** 联系方式占首屏；大段求职意向在展示页置顶（可折叠或置底）。

### L2 · `行业解决方案.md`

**必备章节（1–8）：** 格局 · 挑战 · 框架（含 ASCII/分层图）· 能力地图表 · 产业边界 · 对标 · 风险与权衡 · 文档导航。

**深度要求：**

- 「框架」不只列技术名词，要写清**方法论**（如场景驱动、可降级交付）。
- 能力地图第三列必须是**可验证成果**，禁止与第二列重复堆砌形容词。

### L2+ · `技术方案/`

**必备：** 背景 · 目标与非目标 · 架构/分层 · 关键设计决策（含备选方案与取舍）· 稳定性/成本 · 与 L3 链接。

**篇幅：** 单篇建议 **800–3000 字**（长文可拆「导读 + 完整稿」，如 Virtual Idol、PUBGM）。

### L3 · `项目经验/`（展示核心）

每篇**标杆案例**须包含以下区块（顺序可微调）：

| 区块 | 用途 | sync 是否消费 |
|------|------|---------------|
| frontmatter `featured` / `hero` | 置顶与排序 | ✅ |
| `## 展示摘要` | 卡片/英雄区文案（≤120 字） | ✅ 优先于「一句话」 |
| `## 一句话` | 兼容旧稿 | ✅ |
| `## 技术挑战与约束` | 难点、边界、非目标 | 规划 |
| `## 关键架构决策` | 决策表或 2–4 条 ADR 式条目 | 规划 |
| STAR 四段 | 情境/任务/行动/结果 | 部分 |
| `## 结果` 指标表 | 量化证据 | ✅ |
| `## 技术栈` | 标签 | ✅ |
| `## 文档链接` | L2/L2+ 回链 | — |

**标杆示范：** [架构升级及研效优化](行业解决方案/互联网平台建设与研效/项目经验/2019-2026_架构升级及研效优化.md)

## 3. 写作原则（专业展示）

1. **先矛盾后方案：** 写清「当时最痛的是什么」，再写技术选型。
2. **决策可追溯：** 每条关键决策对应「考虑过什么、为什么没选」。
3. **指标带语境：** 如「18→7 步」要说明**什么流程**、**谁受益**。
4. **脱敏可对外：** 内部系统名可保留腾讯栈；客户数据、未公开口径标注「内部报表」。
5. **一事实一处：** STAR 全文只在 L3；L2+ 写实现；L2 写方法论；禁止三处复制粘贴。

---

## 4. 与 `web/` 同步

```bash
npm run sync:site   # docs → web/data/site.json + index.html
```

| docs 内容 | site.json / 页面 |
|-----------|------------------|
| L1 精选案例表 | `l1.featuredProjects[]` |
| L3 `展示摘要` + frontmatter | 项目卡片排序与文案 |
| L2 章节 1–4 | 产业详情区 |
| L3 技术栈 | 标签 |

**注意：** 改 docs 后必须跑 sync，展示页才会更新；**不要手改** `web/index.html`。

---

## 5. 成熟度自检（单篇 L3）

- [ ] 有 `展示摘要` 或高质量「一句话」
- [ ] 至少 2 条「关键架构决策」含取舍
- [ ] 结果表 ≥ 4 项量化指标
- [ ] 链接到对应 L2+ 技术方案
- [ ] `featured: true` 或 `hero: true`（若属精选案例）
