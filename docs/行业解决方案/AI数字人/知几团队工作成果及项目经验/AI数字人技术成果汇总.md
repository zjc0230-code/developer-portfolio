## 二、参考架构（数字人服务化）

整体架构分为五层：接入层、编排层、能力层、模型层、基础设施层。每层之间通过明确接口通信，实现松耦合。

```
         ┌──────────────┐
  用户 ──►│ 接入层       │ HTTP / WebSocket / SSE / tRPC
         └──────┬───────┘
                ▼
         ┌──────────────┐
         │ 编排层       │ 对话状态机 · 流式管线 · 意图路由
         └──────┬───────┘
                ▼
    ┌───────────┼───────────┐
    ▼           ▼           ▼
  LLM/Agent   TTS/ASR    驱动层(口型/S2G)
    │           │           │
    └───────────┴───────────┘
                ▼
         ┌──────────────┐
         │ 治理层       │ 缓存 · 限流 · 敏感词 · 配置热更
         └──────────────┘
```

## 三、核心技术栈

### 3.1 大语言模型与 RAG 问答

RAG 是 AI 数字人知识问答的核心架构。知识处理分为四阶段流水线：数据采集、知识清洗、知识增强、索引构建。

检索采用多路召回 + 重排序策略：查询理解阶段进行意图识别、实体识别和查询改写；多路召回并行执行向量召回（语义相似度 Top-100）、关键词召回（精确匹配 Top-100）、实体检索和历史召回；重排序模型综合考虑语义相关性、质量分数、时效性和个性化因素。

### 3.2 流式响应架构

核心思想是边生成边推送，首字延迟从秒级降到百毫秒级。系统通过 HTTP/2 流式连接模型服务，每生成一个 token 立即推送。异常处理采用优雅降级策略：已生成超 50% 时继续返回剩余内容并附加错误标记，不足 50% 时立即中断返回兜底话术。

### 3.3 Prompt 工程与版本管理

Prompt 采用模板化设计，包含变量占位符运行时动态填充。设计遵循五要素框架：角色设定、上下文注入、任务描述、约束条件、示例。集中管理支持版本管理、A/B 测试、非技术人员可视编辑、多语言优化。

### 3.4 内容安全审核

输入和输出两个环节均进行敏感词过滤，形成双重审核机制。输出过滤采用异步化（不阻塞主流程），缓存策略分层（违规永久缓存、正常短期缓存），ACE 服务不可用时使用本地词库过滤并增加事后审核。

### 3.5 动态负载控制

负载分为四个等级（0 到 3），级别越高功能越少。级别 0 全功能开放，级别 1 关闭个性化首问，级别 2 关闭游戏数据查询和摘要记忆，级别 3 关闭所有增值功能并拒绝过量请求。支持双向调节（降级与自动恢复），引入防抖机制防止频繁级别切换。

### 3.6 分层记忆管理

记忆系统分为短期记忆（会话级上下文管理，动态滑动窗口）和长期记忆（跨会话提取关键信息，结构化记忆项）。采用分层存储架构（Redis 热层 / MySQL 温层 / 对象存储冷层），摘要生成采用增量方式。

### 3.7 工程优化原则

- 流式优先：首字延迟秒级→百毫秒级
- 缓存分层：TTS、动作标签、热点问答命中率 35%-45%+
- 配置驱动：游戏/IP/机器人/限频热更新，不发版调参
- 四重安全：签名验证、防重放、限流、ACE 敏感词双向检测

### 3.8 服务架构标准化

所有 AI 数字人项目均采用 Go + tRPC 微服务架构。基础设施采用 Redis（分布式缓存和负载控制协调）、Polaris（服务注册与发现）、Rainbow（配置中心热更新）。监控观测层由 Prometheus、SkyWalking、Zap Logging 构成完整可观测性体系。

### 3.9 模型推理服务标准化

模型推理采用 VLLM 框架，核心特性：PagedAttention（KV Cache 分页管理）、连续批处理（请求动态加入和离开批次）、GPU 显存优化。模型代理层实现流量控制与熔断、多模型智能路由、流式响应处理、协议转换。向量模型使用 Triton Inference Server。

### 3.10 多语言与国际化

多语言支持系统性地解决语言特定优化：分离语言无关部分与语言相关部分、语言特定优化（中文礼貌、英文简洁、阿语 RTL）、回退机制（缺失时回退英语）、母语者审核。

### 3.11 部署与运维体系

整体通过腾讯云 EKS 部署，采用微服务集群架构。多环境验证发布流程：国内测试 → 海外新加坡测试 → 北美正式。大模型更新采用热更新 + 挂载方式（模型文件与容器镜像分离），滚动更新保证服务不中断。

### 3.12 场景矩阵

AI 数字人覆盖四大典型场景：虚拟偶像直播（互动延迟 <0.3s，弹幕驱动实时渲染）、私域 AI 小程序（多角色配置、运营自助接入）、智能客服（RAG + 多轮对话 + 全链路监控）、游戏 NPC（精调 + RAG 抗幻觉）。

## 四、项目特有技术

### 4.1 平台与产品

#### 知几游戏 AI 助手平台（VLink）

基于游戏领域知识图谱构建，支持多渠道接入（游戏内/外），实现 AI + 人工协同模式。核心设计包括知识图谱驱动的多轮对话引擎、多游戏标准化接入规范与评测集体系，确保新游戏快速上线。

#### 超核 AI 智能客服系统

针对客服场景的特有设计：多游戏标准化接入规范与评测集体系、AI 边界划分与人工兜底机制（约 5% 复杂问题转入人工）、全链路监控体系建设。

#### 游戏知几私域 AI 小程序

私域场景特有设计：20+ IP 配置化人设管理（每 IP 独立 Prompt、知识库和角色性格）、混元 7B 模型协作评测体系（覆盖拟人度、安全性、事实性）、小程序后端与微信生态集成。

#### AI 驱动 3D 数字人口播内容平台

高写实语音驱动 3D 面部生成技术，高表现低资源语音合成。核心创新是将文本到视频的完整管线产品化，输入文本即可快速输出自定义数字人视频场景与动作。

### 4.2 游戏内 AI 项目

#### 和平精英「和平第五人」

行业首个无可视化界面的纯语音交互 AI 助手。技术突破：纯语音环境下的意图理解准确率保证（无视觉 UI 辅助）、战中实时策略指导的低延迟要求（玩家在激烈战斗中无法等待）、语音指令与语音聊天的自然切换。将 AI 交互从战前战后咨询升级到战中沉浸式策略指导，代表了语音 AI 在游戏场景中的最高难度应用。

#### 天天象棋无障碍版本

将语音指令技术横向扩展到无障碍场景。技术要点：语音指令的容错性设计、无障碍交互的特殊 UX 规范、对棋盘状态的口语化描述生成。

#### 天涯明月刀「绝智阿暖」多模态 NPC

腾讯游戏首个大模型驱动的多模态 AI NPC。特有技术：语音合成与 3D 面部驱动跨模态方案（大模型 TTS + 算子加速实现语音→3D 面部表情端到端驱动）、针对 MMO 高并发场景的性能优化（int8 量化、prefix cache、flash decoding、动态批处理，E2E 时延 10s+→1.5s）、m3e 向量模型用于中文知识库检索、自主行为逻辑设计使 NPC 不仅回答问题还能主动发起交互。ICCV 2023 相关学术成果，开源语音项目获 800+ GitHub stars。

#### PUBG Mobile 智能管家 Lily

海外多地区 10+ 私有化部署，满足各国数据合规要求（数据不出境）。六轮压测迭代验证稳定性。三层服务保障体系（业务层付费分层运营、系统层队列削峰、功能层动态降级）。多模型动态路由（简单意图轻量模型降成本 30%，复杂场景大模型保质量）。GPU 利用率稳定在 ~90%。全链路架构涵盖 13 个微服务的职责分工与协作关系、完整的五大服务调用链路（主对话/历史会话/游戏数据/安全审核/记忆管理）、用户类型差异化权限控制框架。

### 4.3 端外数字人与跨域项目

#### 虚拟人直播与 AI 口播

虚拟人渲染与驱动架构（真人级口型同步和表情驱动）、弹幕驱动互动方案（与虎牙平台合作，弹幕信号实时转化为数字人响应动作和对话）、流式管线优化首帧与端到端延迟（多级缓存和管线编排达到 <0.3s 互动延迟）。

#### 浙江卫视「谷小雨」

国内首个使用虚幻引擎在广电 AR 实时舞台实现实时渲染的高精度写实虚拟人，面数超 200 万。技术挑战：广电级实时渲染的性能要求、AR 舞台虚实融合的精确空间定位、新闻播报场景的高可靠性（直播不容出错）。

#### 穿越火线手游「云悠悠」私域助手

核心技术：IP 人设多端一致性维护（游戏内外同一角色不能出现人设矛盾）、私域流量分发与触达机制、AI 陪伴与攻略服务的差异化定位。

#### AI 直播助手

技术要点：弹幕语义理解与多轮对话融合、解说内容的赛事知识库构建、长时间直播的稳定性保障。

## 六、技术演进路线

- **短期**：情感化长期记忆与跨会话人设一致性的深度实现
- **中期**：视频生成 + 实时驱动融合（AIGC 管线），打通从文字到 3D 表现的完整链路；拓展具身智能提升交互自然度
- **长期**：企微/私域与直播统一数字人底座，构建数字人社交网络让 NPC 之间也能互动，打造全渠道数字人体验
